# Умный дом

[![Render diagrams](https://github.com/ikgali/uml-kabalov-17/actions/workflows/diagrams.yml/badge.svg)](https://github.com/ikgali/uml-kabalov-17/actions/workflows/diagrams.yml)

Учебный проект по практическим работам №1–3: статическая и динамическая модели системы «Умный дом», C4-архитектура и итоговый пакет документации. Система управляет устройствами в квартире: светом, замками, климатом — и следит за состоянием датчиков (протечки, движения, дыма). Пользователи взаимодействуют с домом через Телеграм-бот или голосом через встроенный модуль «Пятница». Жильцы настраивают сценарии автоматизации и активируют режим «никого нет», при котором система переходит в режим охраны. При срабатывании аварийного датчика система формирует уведомление, доставляет его жильцу и при необходимости передаёт сигнал в полицию. Доступ к устройствам разграничен по ролям: взрослый жилец имеет полные права, ребёнок — ограниченные с возможностью временной эскалации привилегий, техник — доступ только к обслуживанию. Уведомления доставляются через основной канал (Телеграм) с резервным каналом на случай ограничений доступа. Модель построена по методологии diagram-as-code: все диаграммы хранятся в виде `.puml`-исходников и собираются в PlantUML.

## Документация

- [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — сводный архитектурный документ по итогам ПР1–ПР3: границы, требования, домен, динамика, C4 и решения.
- [`docs/consistency-check.md`](docs/consistency-check.md) — аудит согласованности модели по десяти пунктам и найденные расхождения.
- [`docs/adr/`](docs/adr/) — архитектурные решения: композиция `Событие` в `Журнал`, отдельный контейнер «Пятница», MQTT для устройств.
- [Успешный прогон CI](https://github.com/ikgali/uml-kabalov-17/actions/runs/43722883613) — GitHub Actions, 17 из 17 диаграмм, PNG и SVG в артефакте.

## Структура репозитория

- `docs/00-setup/` — настройка среды, черновики диаграмм, рефлексия.
- `docs/01-usecase/` — актёры, диаграмма вариантов использования, сценарии, трассировка на FURPS+.
- `docs/02-domain/` — модель предметной области: кандидаты в классы, диаграмма классов, обоснования решений, диаграмма объектов.
- `docs/03-sequence/` — диаграммы последовательности и коммуникации для ВИ-01, сравнение нотаций.
- `docs/04-activity/` — процесс активации режима «Никого нет» с дорожками и поток объекта `Сценарий`.
- `docs/05-state/` — конечный автомат жизненного цикла `Сценария`, таблица переходов и выводы.
- `docs/06-c4/` — C4-модель: контекст, контейнеры, компоненты, динамический вид, развёртывание и Structurizr DSL.
- `docs/adr/` — три архитектурных решения с контекстом, альтернативами и последствиями.
- `.github/workflows/diagrams.yml` — CI: проверка синтаксиса и рендер всех PlantUML-диаграмм.
- `_style.puml` — общий стиль для всех диаграмм.

## C4-модель

| Уровень | Исходник | Что показывает |

| L1 — Context | `docs/06-c4/01-context.puml` | жильца, техника, Телеграм-бот, полицию, устройства и границу системы |
| L2 — Containers | `docs/06-c4/02-container.puml` | Backend API, «Пятницу», MQTT, RabbitMQ, обработчик журнала, сервис уведомлений и PostgreSQL |

## Сборка диаграмм

Нужны Java 21, PlantUML и Graphviz. В репозитории есть локальная сборка инструментов в `Notes/tools/`, но она не коммитится.

```powershell
$files = Get-ChildItem docs -Recurse -Filter *.puml | Where-Object { $_.Name -notlike '_*' }
java -jar Notes/tools/plantuml.jar -failfast2 -charset UTF-8 -tpng -o out @($files.FullName)
```

В CI используется тот же режим `-failfast2`: любая ошибка синтаксиса или отсутствующий include делают прогон красным. Результаты рендера (PNG и SVG) публикуются артефактом workflow.
